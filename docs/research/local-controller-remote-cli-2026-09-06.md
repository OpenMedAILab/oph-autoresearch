# 本机主控与远程 CLI 执行端

## 用户确认的架构

本机主控模型负责研究规划、任务协调、进度解释和结果审核。它可以来自官方/中转 API，或本机已登录的 CLI。服务器上的 CLI 使用服务器自身的账户，是接受任务、执行实验和返回信息的执行端，不作为研究对话的主控模型。

模型设置和对话模型选择器只展示本机主控选项。远程 CLI 的登录状态、模型目录与执行能力展示在 SSH 服务器设置中。启动时后台探测本机和已保存的服务器；连接或目录配置变化后更新。探测状态不是实验批准，也不是模型额度或实验成功的证明。

用户提及的架构图片在本轮环境中缺失。本说明仅依据用户已输入的架构文字，不补造图片内容。

## 当前接线

- `packages/server/src/cli-catalog.ts`：后台探测、服务器去重、错误隔离与位置区分。
- `packages/team/src/cli-probe.ts`：Codex account/read + model/list、Claude auth status + 控制初始化、Grok models；只查询状态和目录。
- `packages/tools/src/ssh.ts`：复用 SSH 认证；ssh_list_files 不传 profile 时返回工作区及 CLI 能力；ssh_run_command 仍经过既有权限机制并拒绝只读连接。
- `packages/server/src/cli-conversation.ts`：本机 CLI 主控的历史、回执与中断；携带远程能力摘要，但不将远程 CLI 作为主控启动。
- `apps/web/src/components/settings/SshSettings.tsx`：展示远程执行端；主控模型目录排除远程条目。

CLI 状态查询与研究执行协议是不同层级。当前原生 CLI 主控不自动拥有应用 API Agent 的工具集合；能力摘要不等于已经建立受控的双向 RPC。不能将 UI 探测完成描述成完整的远程实验调度闭环。

## 下一步待评估的实现方向

1. **复用研究执行协议接入 CLI 后端。** 先核对现有 `research/job-daemon.ts`、`ssh-daemon-client.ts`、`daemon-execution.ts` 与 store 的 Attempt/receipt 事实，扩展结构化任务、状态查询、日志、取消确认和回执；避免另建仅靠 shell 字符串及内存状态的实验队列。
2. **统一主控工具入口。** 为 API 主控与本机 CLI 主控提供同一受控执行端接口，明确 CLI 通过何种 MCP/RPC 调用应用能力，避免依赖 CLI 自行猜测 SSH 密码或旁路权限。
3. **实验批准绑定任务版本。** 区分“SSH 可写”“CLI 已登录”“批准某个实验”；明确 root、资源预算、输入版本和产物范围，拒绝把 CLI 输出中的成功声明当成验收事实。
4. **实现断线后的状态核对。** 持久化 dispatch/job 标识，断线后查询原作业；取消必须有远端确认，不能以本地 SSH 进程退出代替。
5. **构建最小可复现实验闭环。** 在非患者样例数据上验证准备、执行、指标与产物摘要、独立复核，再扩大适用场景；原始数据留在服务器。
6. **补齐跨平台开发验证。** 本轮相关 111 项测试、类型与格式检查通过。全量运行 2384 通过、1 跳过、8 失败及1附带错误；其中新增注释文体问题已修复并单独通过。其余失败涉及 Python 命令、DNS/网络、文件时间戳、Git 监测/PATH 与 Windows cmd 假设，需进一步隔离确认。未进行真实模型推理或实验调度验收。

这是一份待评估的方向清单，不表示以上执行能力均已实现。
