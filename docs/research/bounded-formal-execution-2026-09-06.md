# 有界研究主控与正式执行接线

这一轮延续 Pro 与 Anneal 的方案，Astra 审查和整合，Terra 在独立分支实现。只提供 Web，不打包桌面应用。新建项目必须同时绑定本机目录与已保存 SSH 服务器的工作目录，具体规则见 [双目录绑定](project-workspace-binding-2026-09-06.md)。

## 已实现的边界

- 有界主控只接受已配置价格的 API 模型。独立签署绑定请求数、推进数、输入与输出上限、截止时间、停止阶段和总预留。主控只取得 `research_control` 工具；普通 CLI 不会绕过预算进入此模式。
- 调度持久记录轮次、发送状态、观察依据与代际。远端尚未完成或人类尚未批准时不空转调用模型；审批事实变化可以唤醒，心跳或账本版本本身不能唤醒。重启恢复没有发出的动作；发送结果未知的请求不重投。输入预检失败不会每秒新增一次会话。
- 暂停先落账，再中断本机主控。旧暂停请求的重放不能中断已经恢复的新代际。已获批准的远端执行、租约和清理继续。
- 费用依据与签署结算使用同一账本。未签的人工核账提案不占为已知费用；未知实际费用保留预留，不能被记成零或在执行状态未知时释放。CLI、科学复核、主控、候选代码审阅与正式执行各有独立费用对象。新科学上下文排除财务变化，旧哈希规则保留。
- v3 Attempt 在首次网络操作前持久绑定 authority epoch、发送阶段与 observer generation。提交与取消在远端写事务内检查 epoch。重建远端账本后，旧任务不能被新 authority 接收。

## 候选到正式计划

Web 从已核验候选开始，选择管理员登记的镜像、数据快照和受信评估器，显示名称而非内部标识。候选代码独立审阅需要一次单独的费用批准；实际调用之前已经原子预留，响应丢失只读取原审阅。审阅只接收候选代码和计划，没有会话历史、工具、宿主文件或执行权。服务商未回报实际 usage 时费用仍未知。

接受的代码审阅绑定完整计划，不能用于另一组资源、环境、数据或代码。随后人类独立批准正式执行并冻结计划。刷新后可从持久草案恢复原计划。准备的审批不替代正式执行批准；代码审阅通过也不是科学结论受到支持。

v4 固定入口为 `python3 main.py`，固定只读镜像、禁网络、只读数据和代码挂载、单独输出目录、CPU/内存/进程数及每任务期限。计划的代码哈希是实际 `main.py` UTF-8 字节哈希；候选回执另有完整哈希，保留代码与 patch 元数据身份。不会把 v3 draft JSON 哈希误当作文件哈希。

正式运行通过现有 daemon、固定 SSH tunnel 与远端令牌接口。候选仅在精确批准和绑定持久化后按字节登记；远端固定路径 `wx` 写入，同名只能重用相同哈希。重连观察原作业，取消等待 authority 证明停止。只有完整回执与受信标签独立复算通过的结果进入科学证据；迟到、撤销、取消或无法核验的结果不成为正式成果。

## 管理员配置入口

本机 `oph serve --research-formal-execution <file>` 接收仓库之外的管理员 JSON 文件：

- `catalog.images`：友好 `label` 与已登记镜像 `digest`。
- `catalog.datasets`：友好 `label`、`dataManifestHash`、`labelSetContentHash`。
- `catalog.evaluators`：固定 `id: binary-classification-v1`、友好 `label` 与 `implementationHash`。
- `routes`：固定服务器 profile、连接哈希、项目根目录、authority 身份、准入证据、费用预留和原有 `SshDaemonConfig`。配置文件不进入研究项目，不由模型或 HTTP 接口修改。

远端 `oph research-daemon --config <file>` 的 `formalOci` 只接受管理员固定的 Podman 可执行文件与身份、数据 manifest/只读根目录、受信标签和 evaluator。真实 rootless/cgroup v2 检查失败时不创建正式执行后端。正式准入证据必须来自指定环境验收，不能以手动填入哈希替代运行记录。

重活（数据校验、Podman 运行、预测评估、authority 的 receipt 复验及容器停止确认）在独立 Worker 线程中执行，外层 lease heartbeat 可继续。Worker 无结果退出、异常或缺回执都拒绝完成。目录、回执和预测读取拒绝软链和非普通文件，并限定读取长度。停止确认未完成时保留持久清理状态，不因 worker 消失就宣告容器已停止。

## 工程验收与真实环境验收分开

最终代码提交 `a7be7af` 全量测试 2593 通过、1 跳过、0 失败，共 2594 项 / 222 文件、12809 条断言，耗时 56.35 秒；跳过项仅 Windows junction 平台测试。完整 TypeScript 检查、Web 生产构建及变更文件 Biome 检查通过。本次仅构建 Web，没有打包桌面 App。

正式审阅 API 使用真实 Store 和本机确定性 reviewer fixture 验证批准、并发、幂等和计划身份；主控使用真实 Session 与本地 HTTP SSE 验证发送前预留、工具白名单、usage 和输入拒绝。独立 Worker 的 1.6 秒真实 CPU 计算期间，外层 100ms 心跳持续触发；停止确认的两个 700ms Worker 用例也验证 40ms 心跳可继续。正式证据读取和发布负例覆盖候选、计划、标签、任务修订、作业身份及回执被替换，不把准备产物或隔离结果当成科学成果。

这些 L 测试不等于真实 SSH/GPU/容器 R 验收。当前已配置 SSH 的只读环境探测确认 Linux、cgroup v2 与 GPU 可见，但该服务环境的 PATH 未找到 Podman/Docker；没有安装系统运行时，没有调用远端模型或开展用户数据实验。正式环境仍未准入。严格超过十分钟的成功计算、容器资源/网络/目录边界与重启清理都需要在具备真实 rootless OCI 的环境中另行取得记录。当前输出目录采用管理员指定的宿主挂载，代码尚未实施输出磁盘配额；真实准入还必须取得有界输出存储的配置与验证记录。Linux 检查脚本仅探测前置条件，成功不代表完成准入验收。

当前有界主控的自动停止阶段为获得候选或完成科学独立复核；正式实验仍由 Web 的精确人类批准路径发起。全文证据自动化、完整期刊稿件、多设备调度和 Skill 行为晋级是后续研究能力，不能从本地候选测试推导为已通过。
